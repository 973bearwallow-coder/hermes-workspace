      4. Self-Hosted Cursor — What Leaves the Network


 STARTER
 Cursor's self-hosted docs split the loop. Cursor still runs inference, planning, and the agent loop. Your worker
 runs the tools. Personal machines use a user login or API key. Team pools need Enterprise plus a service
 account key. Admins can allow or require self-hosted. You can connect up to 200 workers per user.
 Cursor-managed Cloud Agents remain the default for most teams. Spark is a whiteboard: draw what stays on
 the worker, what goes to Cursor, and what a client would not sign.



 KEEP GOING
    • Draw the trust boundary — model in Cursor's cloud, shell on your box. Acceptable?

    • Personal My Machines, or only a team pool on a VM?

    • Require self-hosted for client work, or keep Cursor-managed for speed?

      7. Skills vs MCP — Pick a Lane for Review


 STARTER
 GitHub's agent-skills docs and the July 29 changelog draw a clean split. A SKILL.md under .github/skills
 teaches Copilot how your team reviews. An MCP server pulls live context from issue trackers and docs. Both
 now show up as attribution on review comments. MCP in review is read-only. Cursor and VS Code have their
 own MCP clients, so the same server can appear in three places with three permission models. Spark is a
 packing list. One skill, one MCP, one repo — ship it this week or say why not.
